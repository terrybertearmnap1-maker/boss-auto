# boss-auto 迁移操作手册

> 目标：把整套系统（后端 + 浏览器扩展 + 数据 + 配置）从一台电脑完整搬到另一台，
> 搬完后新电脑能直接搜岗位、打分、投递。
>
> 预计耗时 **15–20 分钟**。跟着做，每一步都有验收点。

---

## 0. 先搞清楚要搬什么

系统分两部分，放在两个仓库：

| 仓库 | 内容 | 可见性 |
| --- | --- | --- |
| `boss-auto` | 代码：Agent 流水线、后端、扩展、看板、测试 | **Public** |
| `boss-auto-local` | 私密数据：简历、简历脚本、投递数据库、简历解析结果 | **Private** |

为什么要分两个：代码可以公开，但**简历里有真实姓名、手机号、邮箱、学校**，绝不能进公开仓库。

搬完之后，新电脑上应该是这样的结构：

```
D:\
├─ boss-auto\               ← 公开代码（git clone）
│  ├─ jobpilot\             ← 后端
│  │  ├─ .env               ← 你自己建（不在任何仓库里）
│  │  ├─ jobpilot.db        ← 由 private 仓 import 回来
│  │  └─ data\current_resume.json
│  ├─ extension\            ← 浏览器扩展
│  ├─ resume\               ← 简历成品（import 回来）
│  └─ private\              ← 简历脚本（import 回来）
└─ boss-auto-local\         ← 私密数据仓库（git clone）
```

`.env` 里有 API Key，**两个仓库都不放**，新电脑手动建一次。

## 3. 配置 git 代理（国内必需）

直连 GitHub 大概率超时。如果你本机有代理（Clash / v2ray 等），先确认端口：

```powershell
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 7890,7897,10809 } | Select-Object LocalPort
```

拿到端口后配置（只对 github.com 生效，不影响其它仓库）：

```powershell
git config --global http.https://github.com.proxy http://127.0.0.1:7897
```

**验收**：

```powershell
git ls-remote https://github.com/terrybertearmnap1-maker/boss-auto.git
```

能列出 `refs/heads/main` 就说明通了。如果报 `Could not connect ... 443`，说明端口不对或代理没开。

> 没有代理怎么办：用手机热点试，或者把仓库下载成 ZIP（但 ZIP 没有 git 历史）。

## 10. 重填扩展设置（**最容易漏的一步**）

扩展配置存在 Chrome 的 storage 里，**不跟仓库走**，必须重填。

点扩展图标 → 设置页，按下表填写：

### 10.1 筛选条件

| 字段 | 填写 |
| --- | --- |
| 岗位关键词 | `Agent,大模型,AI应用,智能体` |
| 排除关键词 | `java,后端,服务端,产品经理,销售,客服,运营,标注,训练师` |
| 城市 | `广州,深圳` |
| 期望薪资 | `4` — `10` |
| 薪资匹配方式 | 只卡下限 |
| 经验要求 | `应届,经验不限,1年以内` |
| 经验匹配方式 | 不限制 |
| 学历要求 | `本科,硕士,学历不限` |

### 10.2 简历与匹配

| 字段 | 填写 |
| --- | --- |
| 核心技能 | `Python,Agent\|智能体,LLM\|大模型,RAG\|检索增强\|知识库,LangChain\|LangGraph,Prompt\|提示词` |
| 加分技能 | `FastAPI,Docker,SQL,向量数据库\|向量检索,工具调用\|Function Calling,MCP,微调\|Fine-tune,多模态` |
| **匹配结果上报地址** | `http://127.0.0.1:8030` |
| 最低匹配分 | `60` |

> ⚠️ 上报地址不填，后端收不到任何数据，看板永远是空的。

### 10.3 打招呼语

**方式 A：扩展本地发（不依赖后端）**

```
您好，我是27届本科应届生，投递「{岗位}」（{公司}）。看到要求里的{技能}我都有实际项目经验，方便聊聊吗？
```

支持占位符：`{岗位}` `{公司}` `{技能}` `{城市}`，会按每个岗位替换。

**方式 B：后端按 JD 生成（每条都不同）**

勾选 **「自动执行后端下发的投递指令」**，话术由后端 LLM 生成，扩展只负责执行。

> 方式 B 需要后端常驻，并且**保持一个 BOSS 标签页打开**（轮询器在页面脚本里）。

### 10.4 频率与安全

| 字段 | 建议 |
| --- | --- |
| 每日上限 | `20` |
| 单轮上限 | `2`（首次验证）/ `8`（稳定后） |
| 投递时段 | `10:00-11:30` / `14:00-16:00` |
| 操作间隔 | `25` — `75` 秒 |
| 演练模式 | 首次勾上，跑一轮确认无误再取消 |
| 总开关 | ✅ |

**验收**：保存后点「打开投递页」，BOSS 页面右下角出现面板并显示「已筛选 N 个岗位」。

原来的定时任务不会跟过来。推荐用 Windows 任务计划程序（不依赖任何常驻程序）：

2. 名称：`BOSS 自动投递-上午`，触发器：每天 `10:00`
3. 操作：启动程序
   - 程序：`C:\Program Files\Google\Chrome\Application\chrome.exe`
   - 参数：`https://www.zhipin.com/web/geek/jobs?bossauto=1`
4. 重复一次，时间改成 `14:00`

**验收**：任务列表里出现两条，右键「运行」能打开 BOSS 页面并自动开始投递。

## 15. 日常维护（两台机器同步）

在**正在用的那台**上：

```powershell
cd <项目>\jobpilot
python -m pipeline.backup export D:\boss-auto-local
cd D:\boss-auto-local
git add -A
git commit -m "sync: 更新数据"
git push
```

另一台：

```powershell
cd D:\boss-auto-local
git pull
cd D:\boss-auto\jobpilot
python -m pipeline.backup import D:\boss-auto-local
```

> 数据库是二进制文件，两台机器同时改会冲突。**建议固定一台作为主用机**，另一台只在切换时 pull。

## 16. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `python` 不是命令 | 装 Python 时没勾 PATH | 重装并勾选，或改用 `py -3` |
| `ModuleNotFoundError: langgraph` | 依赖没装 | `pip install -r requirements.txt` |
| `git clone` 卡住 | GitHub 连不上 | 配代理（第 3 步） |
| `Repository not found` | 登录账号不对 | `cmdkey /delete:git:https://github.com` 后重试 |
| 看板打不开 | 端口被占用 | 查 8030 占用进程，或换端口 |
| 看板表格空 | 没上传简历 / 没导入 db | 上传 PDF 或第 7 步 import |
| 扩展面板不出现 | 没加载扩展 / 页面是旧脚本 | `chrome://extensions` 重载，再按 F5 |
| 面板 0 命中 | 关键词太窄 / 城市不对 | 放宽设置页关键词 |
| 投了但 BOSS 没消息 | 演练模式没关 | 检查设置页勾选 |
| 后端有数据但看板不更新 | 上报地址没填或填错 | 设置页改成 `http://127.0.0.1:8030` |
| 指令一直 `queued` | 没有开着的 BOSS 标签页 | 保持一个 BOSS 页面打开 |

## 附录 B：首次建立私密仓库

如果 `boss-auto-local` 还没建过：

```powershell

cd <项目>\jobpilot
```
